# KMT Operator Lab — ブラウザ操縦席 初期版

## 位置付け

2026-09-20、`main` の `36cd859`（残監査項目対応）を取り込んで実装した、人間操作と自動制御の接続を試す初期版です。既存物理コードは変更せず、`FlyingBoatVehicle(spatial=True)` を使用します。

- ブラウザ：Three.jsによる外景、前方／追従視点、速度・高度・昇降率・方位・バンク計器。
- 入力：標準Gamepad mapping、校正画面、キーボードとスライダーによる代替操作。
- モード：ハイブリッド／手動／見学。開始地点は水上・巡航・着水進入から選択。
- 安全側の扱い：入力切断・通信断・タブ離脱・処理遅延で停止。再接続は明示的な再開が必要。
- 記録：操作要求、物理tickで採用した入力seq、適用制御、状態、イベント、結果JSON。

**実機訓練装置ではありません。ピッチ／バンク指令追従の簡略モデルです。表示される成功は実機の安全性や操縦技能を認定しません。**

## 起動

Python 3.11以上、Node.js 22を推奨します。リポジトリのルートで：

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-operator.txt
cd web/operator
npm ci
npm run build
cd ../..
python run_operator.py
```

`http://127.0.0.1:8000` をブラウザで開きます。Windowsでは仮想環境の有効化を `.venv\Scripts\Activate.ps1` 等に読み替えてください。

フォント・Three.jsを含めフロントの実行資産はビルドに同梱します。ビルド後の外部CDN接続は不要です。従来の学習・評価CLIにはFastAPI等のWeb依存を追加していません。

### 共有プレビュー／リバースプロキシ

```bash
python run_operator.py --host 0.0.0.0 --port 8000
```

初期の許可Hostは `localhost,127.0.0.1,*.e2b.app,testserver` です。独自ホストには `OPERATOR_HOSTS` を指定します。TLS終端の構成により同一Origin判定が一致しない場合、**実際の公開URLだけ**を `OPERATOR_ORIGINS=https://your-host.example` に指定してください。ブラウザ側は相対APIと現在のホストへのWS/WSSを使います。

公開サービス向けの利用者認証は未実装です。LAN・クラウドではプラットフォーム側のアクセス制御または認証付きプロキシが必須です。Cookieは操作権限の所有とクロスサイト防御に使いますが、利用者本人の認証ではありません。

1プロセス・1操作者です。複数workerで起動しないでください。最初の接続ブラウザにサーバー存続中の操作権限が割り当てられ、別ブラウザ・別タブによる奪取を拒否します。別ブラウザへ交代するときはサーバーを再起動してください。操作者のCookieを削除した場合も同様です。

埋込みプレビューではCookieやGamepad APIが制限されることがあります。その場合は**別タブでプレビューを開く**ことを推奨します。

## 最初の操作

1. 初回はキーボードのまま、HYBRID・水上・Hs=0.3・seed=42を選びます。
2. 「セッションを作成」→「飛行開始」。内蔵制御が離水し、高度25mを目標に飛行します。
3. 入力モニターは「要求 / 適用」を表示します。スロットル等の入力を自動制御の適用値へ合わせます。
4. 安定飛行1秒、入力一致0.5秒の条件を満たしたら「操縦を引き受ける」。確認後に `YOU HAVE CONTROL` へ変わります。条件未達なら権限を維持して理由を表示します。
5. 「一時停止」で物理・海面時刻・損傷進行を凍結します。手動再開には適用値への入力一致が必要です。
6. 「試行を終了」で結果を確認し、結果JSONを保存できます。

入力一致の許容差：スロットル0.05、ピッチ2°、バンク3°、ラダー0.1。自動制御が大きく変化している離水直後ではなく、巡航へ移って落ち着いた時点で合わせてください。

### キーボード

- W / S：推力の増減（離すと現在値を維持）
- ↑ / ↓：機首下げ／上げ
- ← / →：左／右バンク
- A / D：左／右ラダー
- Space：停止
- スライダー：各軸の連続値。姿勢キーを離すと該当する姿勢入力は中立へ戻ります。

フォーム入力中は操縦キーとして扱いません。モード・開始地点の変更は新しい試行として作成してください。入力デバイスの変更も一旦試行を終了して行います。

### ゲームパッド

USB接続を推奨します。画面で「ゲームパッド」を選び、パッドのボタンを一度押して認識させます。

1. スティック中立、右トリガ解放で「中立を記録」。
2. 左スティック上下左右・右スティック左右・右トリガを端まで動かし、範囲を確定。
3. 入力モニターで符号を確認してチェックを入れる。
4. セッションを作成。

| 入力 | 機能 |
|---|---|
| 左スティック上下 | 手前で機首上げ、奥で機首下げ |
| 左スティック左右 | バンク±25° |
| 右スティック左右 | ラダー±1 |
| 右トリガ | 推力0..1。解放すると0 |
| 下側フェイスボタン | READYでは開始、飛行中は手動引受け、着水要求中は確認 |
| 右側フェイスボタン | 要求取消 |
| 右肩ボタン | 自動着水要求 |
| Menu / Options | 停止 |

ピッチ範囲は入門用 -8..12°。画面の再開ボタンで再開します。初期版ではブラウザの `mapping="standard"` のみを受け付け、非標準mappingの任意割当・校正の永続保存は未実装です。XboxとDualSenseの実機接続試験はまだ行っていません。

## 自動着水と評価範囲

「自動着水を要求」は即時の操縦権切替ではありません。初期の**実験用ゲート**：

- 高度20–30m、対気速度11–15m/s、降下率0.5–2.5m/s
- 原点から東西方向の横ずれ±10m、機首は北±10°、バンク±8°
- 機体が故障していない

未達項目を画面に表示し、すべて満たして確認するとAUTOになります。任意位置・任意姿勢からの捕捉保証はありません。初回は「高度25m・進入」から開始して制御を観察できます。

見学モードも巡航からの着水移行は人間の要求・確認が必要です。自動的な周回→進入経路生成は未実装です。外景のリングは方向・高度の目安で、通過採点はしません。

初接触時の鉛直速度・荷重・横安定条件で結果を決めます。`TOUCHDOWN_OK` は水上減速・停止を含みません。荷重は20Hzの標本最大値で、サブステップ内の瞬間最大値ではありません。試行時間は最大600シミュレーション秒です。

## ログと通信

保存先：`var/operator_sessions/<session-id>/`。Git管理対象外です。

- `config.json`：設定、操作包絡、NumPy版、PythonソースSHA
- `inputs.jsonl`：RUNNING中の入力要求
- `ticks.jsonl`：正規状態・適用入力seq。AUTO中は `applied_input_seq=null`
- `events.jsonl`：開始、引継ぎ、停止、終了、拒否
- `summary.json`：終了理由と基本指標（終了時に原子的に置換）

クライアント時刻で物理を進めません。物理は固定20Hz、入力は約29Hz、テレメトリは20Hz、heartbeatは5Hz。人間入力が250ms、heartbeatが500ms途絶えた場合は停止します。サーバー処理が100msを超えて遅延した場合も停止します。描画・通信が詰まったときに、経過時間分の物理を一気に進めません。

通信は `/ws` の `hello/create/input/event/heartbeat/state/ack`、HTTPは `/api/capabilities` と `/api/summary` です。Origin、署名Cookie、接続epoch、seq、event_id、入力範囲、メッセージ長・頻度を検証します。イベントは単一イベントループ上でtick間に処理します。物理の同時書換えはありません。

## 設計書からの初期版の差分・残課題

- P0–P2相当の接続と操作、一部P3（ログ・終了サマリ）まで。段階的課程、時間重み付き採点、履歴リプレイ、教官画面は未実装。
- フロントは依存を抑えたJavaScript ES Modules＋Vite＋Three.js。TypeScript/React化とスキーマ自動生成は未実施。
- 海面は格子配信ではなく、物理モデルの全波成分と位相を初回に配信し、描画時刻で計算。頂点での値は正規海面と一致するテストを実施済み。近傍メッシュは96m四方・49×49頂点。**三角形内の補間誤差と遠景近似は未認定**。
- 記録は小さな同期追記で、書込み失敗時は停止。非同期書込みキュー、容量quota、UIからの全ログexport・削除は未実装。ローカルディスク使用量は運用者が管理する。
- 通信品質の表示・停止はあるが、専用のRTT時系列ログや正式な無効試行分類は未実装。現在はイベントの停止理由・停止回数を確認する。
- 海況は0 / 0.3 / 0.6m、風なしに限定。進入ゲートの包括的な包絡検証は未完了。
- P4の実パッド／複数OS受入、実ユーザーによる訓練効果、30/60FPSの端末別性能評価は未完了。

## 検証手順

```bash
python -m pip install -r requirements-operator-test.txt
python -m unittest discover -s tests
npm test --prefix web/operator
npm run build --prefix web/operator
```

ブラウザの自動試験（新規起動したサーバーに対して実行）：

```bash
python -m playwright install chromium
python scripts/check_operator_browser.py
```

終了後はサーバーを再起動して、試験用ブラウザが保持する操作権限を解放してください。`OPERATOR_URL` と `CHROMIUM_EXECUTABLE` で試験URL・Chromiumを指定できます。

実施済み：Python128件PASS（既存113＋コア10＋Web5）、フロント入力3件PASS、ビルド成功。Chromiumで作成→自動離水→手動引継ぎ→停止→再開→終了、390px幅での横はみ出しなし、未処理JavaScript例外なしを確認。別途ヘッドレスでHs=0.3/seed=42の自動着水は21.8秒で `TOUCHDOWN_OK`。これらは実パッド対応や訓練効果の検証の代用ではありません。
