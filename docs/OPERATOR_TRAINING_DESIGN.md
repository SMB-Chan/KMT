# ブラウザ操縦席による人間操作者育成 — 基本設計

- 日付：2026-09-20
- 状態：実装前の設計案（実パッド・性能・訓練効果は未検証）
- 対象基盤：KMT、監査修正 c70d4ef を含む現行ソース
- 対象利用者：Xbox / DualSense 等の市販ゲームパッドを使う訓練者
- 本文の数値は、既存実装の値と明記したもの以外は初期設定案。検証後に確定する。

## 1. 目的と範囲

ブラウザに外景・計器・操作案内を表示し、Python の既存物理モデルで飛行を進める。主目的は姿勢・速度・進入の判断、手順、オートパイロットとの役割分担の練習である。

初期版で提供するモード：

1. **見学**：自動離水・飛行・着水を観察する。
2. **ハイブリッド**：自動離水 → 明示的引継ぎ → 手動飛行 → 条件付き自動着水。
3. **手動**：離水から着水まで人間が4軸を操作する。

ここで「手動」は推力・ピッチ指令・バンク指令・ラダー指令を人間が与えることを意味する。現行モデルは6自由度剛体でも実操舵面のモデルでもなく、ピッチは直接指令、空中バンクは一次遅れで追従する。実機操縦資格、操縦感覚、実機の回復性能を保証しない。

初期版の対象外：実機接続、複数人同時操縦、インターネット公開サービス、VR、触覚再現、汎用自動回復、RL再学習、任意姿勢からの自動着水、Ollamaを介したリアルタイム制御。

## 2. 設計原則

- **Pythonが唯一の正規状態を持つ**。採点・接水・損傷・終了判定もサーバーで行う。
- 描画と物理を分離し、ブラウザのFPSや通信間隔で物理刻みを変えない。
- 操縦権限は常に一つ。表示と実際の入力採用者を一致させる。
- 不明な入力や通信断を、操作者の意図として推測しない。初期版は停止する。
- 外景の海面と接触計算に同じ波面を用いる。訓練領域に装飾用の別波を重ねない。
- 訓練条件、補助、通信品質、操作要求と適用結果を記録し、成績の比較可能性を保つ。

## 3. システム構成

```text
ゲームパッド（USB推奨、Bluetoothは個別検証）
        ↓ Gamepad API
ブラウザ：TypeScript / Three.js / HTML・SVG
  校正 → 操縦席 → 結果レビュー
        ⇅ 同一オリジン /api と /ws
Python：FastAPI / Uvicorn（任意依存）
  セッション・操作権限・入力検証・固定刻み実行
        ↓ 一つの物理所有スレッド
  FlyingBoatVehicle(spatial=True)
  DirectionalOcean / Atmosphere / 損傷 / 内蔵制御
        ↓
  操作・状態・イベント・成績の記録
```

初期版は1サーバープロセス・1実行セッション・1操作者。追加接続は操縦権を奪えず、重複操縦接続を拒否する。複数Uvicorn workerは禁止。物理所有スレッド以外から機体を書き換えない。

推奨配備は同一PCのブラウザ＋Python。開発時はViteが `/api` と `/ws` をPythonへプロキシする。配布時はビルド済み画面もPython側から提供する。ブラウザコードに `localhost` のバックエンドURLを埋め込まない。

Arenaプレビュー等ではサーバーは `0.0.0.0` にbindし、許可する公開ホスト・Originを環境設定で指定する。HTTPSページにはWSSを使用。Gamepad APIの安全なコンテキスト、iframeの `gamepad` 権限、ブラウザのユーザー操作要件を診断画面で案内し、必要ならプレビューを別タブで開く。

## 4. 既存コードへの接続

| 既存要素 | 利用方針 |
|---|---|
| `FlyingBoatVehicle.step(dt)` | 空間モード・dt=0.05秒で更新。空間積分器内部は最大0.01秒 |
| `SpatialControl.apply(vehicle)` | 手動4軸の適用経路。RL用正規化action経路と混在させない |
| `send_command` | 自動離水・高度維持・着水へ遷移するときに発行 |
| `send_servo` | `SpatialControl` 経由で利用。ブラウザから任意PWM/APIを受け付けない |
| `read_telemetry` / `observe` | 型付き画面用スナップショットに変換する参考・入力源 |
| `wave_elevation` / 海面モデル | 接触位置と描画用海面の算出 |
| `flight_diagnostics` / 損傷状態 | 記録とレビュー用指標 |
| `fly_ollama.py` のログ規約 | 形式の考え方を継承。人間操作用スキーマは別に版管理 |

現行 `SpatialControl` のピッチ範囲は -8..15°。RL系 -8..12°とは異なる。初期の初心者課程は -8..12°、拡張課程のみ -8..15°とし、実効範囲をセッション設定・HUD・記録で明示する。バンク上限は初心者±25°、拡張±45°、ラダーは±1。クライアントとサーバーが別々の定数を持たず、接続時に制御仕様を配信する。

`send_servo` は航法指令を解除するため、自動中に人間のサーボ指令を送ってはならない。1 tickで採用する制御源を先に決定し、4軸を一括で適用してからstepする。着水自動への移行時は航法指令を明示的に再設定する。

新規ファイルを `operator.py` と命名しない（Python標準ライブラリと衝突する）。

## 5. 操縦席とゲームパッド

### 5.1 画面

- 中央：前方外景、地平線、海面、課題マーカー。追従視点にも切替可能。
- 計器：対気速度、対地速度、平均水面基準高度、直下波面からの船底クリアランス、昇降率、姿勢、方位、スロットル。
- 常時表示：操作権限（AUTO / HUMAN）、訓練段階、補助の有無、PAUSED、入力鮮度、通信遅延。
- 警告：速度余裕不足、過大降下、損傷、波面表示未同期、ゲームパッド切断。
- 教材：次の操作を一つずつ提示。色だけに依存せず文言・形も使う。

計器の速度・高度の定義を省略しない。モデルが与える高度は計器誤差込みの実機高度計ではない。接水荷重・浸水等は「シミュレーター診断」として区別する。

### 5.2 初期割当

| 操作 | Xbox / DualSenseでの共通役割 |
|---|---|
| 左スティック上下 | ピッチ。手前で機首上げ |
| 左スティック左右 | バンク。右で右旋回方向 |
| 右スティック左右 | ラダー |
| 右トリガ | 絶対スロットル0..1 |
| 左右肩ボタン | 離水／着水オートの要求画面（即切替しない） |
| 下側フェイスボタン | 確認・引受け |
| 右側フェイスボタン | 要求取消 |
| Menu / Options または画面ボタン | 一時停止 |

トリガを離すと推力が下がることを教材に明示する。将来の増減式スロットルは別プロファイルとし、初期版には混ぜない。

### 5.3 校正と入力処理

1. Gamepad API・権限・接続状態を確認し、ボタン操作でデバイスを選ぶ。
2. 中心、各軸方向、全ストローク、トリガ最小最大、ボタン位置を対話的に確認。
3. 標準mappingがあっても視覚的に確認。未知のmappingは校正完了まで開始不可。
4. デッドゾーン初期値5%（調整可）、範囲再正規化、反転、任意の感度曲線を適用。
5. ピッチは中心0°、負側と正側それぞれの範囲へ変換。トリムは初期版なし。
6. ブラウザ側で校正済み4軸値を送る。サーバー側で型・有限値・範囲を再検証。

接続番号を恒久IDとみなさない。接続変更は停止と再確認を要求する。校正設定はローカル保存し、セッションにも設定ハッシュを記録する。ユーザーエージェントや機器名の収集は必要最小限とする。

## 6. 状態機械と引継ぎ

ライフサイクルと操作権限を分離する。

- ライフサイクル：`SETUP → READY → RUNNING ↔ PAUSED → FINISHED/ABORTED`
- 操作権限：`AUTO` / `HUMAN`（RUNNING中は必ず一つ）
- 課程段階：`TAKEOFF / CRUISE / APPROACH / TOUCHDOWN`
- 保留要求：`NONE / OFFER_MANUAL / REQUEST_AUTO_LAND`

### 6.1 ハイブリッドの流れ

| 遷移 | ガード・処理 |
|---|---|
| READY → 自動離水 | 校正済み、通信健全、開始確認。armし離水指令を1回発行 |
| 自動離水 → 引受け可能 | 課程の高度・速度・姿勢範囲を一定時間満たす。AUTOを維持したまま通知 |
| 引受け可能 → HUMAN | 人間が確認し、操作値が現在の制御値に近い。次tick境界で権限移動 |
| HUMAN → 着水要求 | ボタンで要求するだけ。条件を評価し、未達理由と進入案内を表示 |
| 着水要求 → 自動着水 | 校正済みの進入ゲート内で確認。次tickでAUTOへ切替 |
| 初接触 → FINISHED | 初接触状態・荷重・降下率を記録して停止 |

引受け可能の初期目安：高度8m以上、対気速度1.3 V_stall以上、|Vz|<2m/s、|bank|<10°を1秒持続。これは保証済み包絡ではない。実機サイズや風条件ごとの検証で確定する。

入力一致の初期目安：スロットル差≤0.05、ピッチ差≤2°、バンク差≤3°、ラダー差≤0.1を0.5秒。画面に現在の自動指令と人間入力を並べる。一致しなければ切り替えず、スティック／トリガ位置の調整を案内する。自動復帰や再接続による勝手な権限変更はしない。

### 6.2 自動着水の制約

既存着水制御は、任意の旋回・横ずれ・速度から着水地点へ誘導する汎用進入装置ではない。初期課程は既存検証に合わせた直線進入、水面上25m付近・約13m/s・8°降下を基準に**実験でゲート幅を校正**する。課題航路はこの進入方向へ戻る構成とする。

ゲートは高度・対気速度・降下率・機首方位・バンク・横ずれ・損傷・海況の許容範囲を持つ。単なる固定速度の比較で対応済みとしない。ゲート外で着水AUTOを押しても状態を瞬間移動しない。練習用の「進入から再開」は新しい試行として扱う。

手動モードでAUTOを使った試行は「補助あり」に再分類する。初期版の一時停止は回復AUTOではない。

### 6.3 停止・再開

通信・入力の異常時は機体状態、損傷、シミュレーション時刻を凍結する。再接続で自動再開せず、状態同期・校正状態・入力一致・ユーザー確認を要求する。PAUSED中も接続監視と画面表示は続く。タブが復帰したときに経過時間分の物理をまとめて進めない。

初期版は接水時点までの訓練。水上減速・停止までの着水完了は別課程とし、初接触成功を「安全に停止済み」と表現しない。

## 7. 実時間実行と通信契約

### 7.1 更新周期

- 物理：固定20Hz（0.05秒）、空間系内部の最大0.01秒刻みを維持。
- 操作送信：最大30Hzを初期値とする。ブラウザは描画フレーム毎にパッドを読む。
- テレメトリ：20Hz。描画は60FPS目標、2スナップショット間の補間。
- 海面パッチ：10Hzを初期値、帯域・位相誤差を測定して調整。

物理tickで最新の有効入力を一度だけ採用する。軸入力はキューを伸ばさずlatest-only、モード変更イベントは順序・ACK付き。単調時計でスケジュールし、最大2tickまで追いつき実行、それを超える遅延は `SIM_OVERRUN` で停止する。可変dtや無制限catch-upは禁止。

### 7.2 API案（version 1）

- `GET /api/capabilities`：スキーマ版、操作範囲、課程一覧、機能。
- `POST /api/sessions`：課程・モード・環境・seedからセッション作成。
- `GET /api/sessions/{id}/summary`：成績・実行条件。
- `GET /api/sessions/{id}/export`：完了したセッション記録。
- `WS /ws/sessions/{id}`：入力、イベント、ACK、状態、海面。

操作例：

```json
{"v":1,"type":"input","session_id":"…","epoch":2,"seq":104,
 "control":{"throttle":0.65,"pitch_deg":3.0,"bank_deg":-5.0,"rudder":0.0}}
```

接続時 `hello` でepoch、実効操作範囲、課程設定、現在の権限・状態を配信する。再接続時はepochを更新し旧接続の入力を拒否。seqは接続内単調増加、重複・逆順は適用しない。クライアント時計は物理制御の根拠にしない。

イベントには `event_id` を付け、`take_control` / `request_auto_land` / `confirm_auto_land` / `pause` / `resume` / `abort` を許可する。ACKは受理／拒否理由と適用tickを返す。重複event_idは再実行しない。機体属性を任意に変更する汎用コマンドは公開しない。

状態配信は `tick, sim_time_s, lifecycle, phase, authority, last_input_seq, applied_control, position_neu_m, velocity_neu_m_s, attitude, airspeed_m_s, wave_clearance_m, damage, warnings` を含む。単位と座標をスキーマに固定する。

入力がサーバー受信基準で250ms更新されなければ停止する。AUTO中も操作者のheartbeat断500msで停止。切断・visibilitychange・ゲームパッド切断は可能なら即停止通知するが、サーバーwatchdogも必ず残す。初期の遅延警告目安はRTT100ms、継続RTT250ms超では停止を要求する（初期値は実測調整）。

WebSocketは順序保証された通信だが、遅い受信先への送信を無制限に貯めない。最新状態を優先し、送信詰まり・古い受信ACKの継続は停止する。イベントと記録の欠落は黙認しない。

### 7.3 入力とアクセスの検証

JSONスキーマ、メッセージ長上限16KiB、入力頻度上限60件/秒、型・範囲・有限性を検証。NaN/Infinity、boolの数値代用、未知コマンドを拒否する。壊れた操縦入力は適用せず停止し理由を返す。

許可Origin／Hostを限定し、セッション所有者を推測不能な資格情報で検証する。同一オリジンのHttpOnly/SameSite cookieを基本とし、状態変更HTTPはOriginとCSRF対策を行う。認証値をURL・ログへ残さない。ローカルサーバーでも任意Webサイトからの操縦を許さない。共有サンドボックスでの公開はプラットフォームのアクセス制御も併用する。

## 8. 外景と海面の整合性

座標はモデルの北・東・上（NEU）を明示的にThree.jsへ変換する。描画座標を `X=東, Y=上, Z=北` とする。姿勢はモデルのheading・pitch・bankから前方／右／上ベクトルを生成して変換し、Euler角をそのまま流用しない。北進・東進・右バンクの符号テストを置く。

初期案は機体近傍128m四方・65×65格子の海面高さをサーバーで計算して配信する。float32高さ配列のみで約17KiB/回、10Hzで約170KiB/秒＋ヘッダ。格子原点・間隔・シミュレーション時刻を添付し、バイナリ配信する。海面計算は物理とは別に予算管理し、必要ならバッチ計算する。

機体と海面は同じ描画用時刻に補間する。遠景は簡略化できるが、近傍接水領域は別位相の装飾波を使わない。パッチ欠落時は同期異常を表示し、一定時間続けば訓練停止。波面が取得できない場所を勝手に平水面として描かない。

格子間隔2mで十分かは未確定。機体／フロート接触位置で補間した描画海面と正規海面を比較し、訓練海況で高さ誤差95パーセンタイル≤0.05mを初期目標にする。満たさなければ格子細分化・更新頻度変更・波成分配信へ移行する。受入前に表示整合性を数値測定する。

## 9. 課程・成績・ログ

### 9.1 初期課程

| 課程 | 内容 | 主な指標 |
|---|---|---|
| 0 | 校正・停止・引継ぎ練習 | 誤操作、応答、手順達成 |
| 1 | 自動離水後に直線飛行 | 高度・速度・針路の誤差、逸脱時間 |
| 2 | 小バンク旋回と復帰 | 過大バンク、高度損失、航路復帰 |
| 3 | 手動で進入ゲートへ到達、自動着水 | ゲート達成、介入、引継ぎ品質 |
| 4 | 手動離水 | 速度管理、離水時姿勢、接触・損傷 |
| 5 | 手動着水 | 初接触時降下率・荷重・横ずれ・損傷 |

海況・風を固定した基礎課程から始め、成功後に外乱を追加する。練習seedと評価seedを分離し、評価では補助と難度を固定する。

### 9.2 評価

初期版は根拠のない0–100総合点より、合否条件と実測指標を表示する。課程の許容範囲はバージョン管理する。

- 高度／速度／針路誤差：シミュレーション時間で重み付け。針路差は±180°にwrap。
- 操作量・変化量、目標範囲内時間、警告時間、AUTO介入回数。
- 接水時の鉛直速度、取得可能な接触荷重のピーク、浸水、スリング。
- 中断・通信断・パッド断は技能不合格と混同せず `invalid/aborted` とする。
- サブステップ瞬間荷重を記録できない場合は「20Hzサンプルの最大値」と明記する。

保護・補助を使った成績と無補助手動の成績を混ぜない。完全人間操作でも機体モデル内の指令追従は残ることを明記する。

### 9.3 記録と再生

保存案：`var/operator_sessions/<UUID>/`（実装時にGit ignore対象へ追加）。従来の追跡済み `results/` を置換しない。

- `config.json`：課程版、モデル／ソースSHA、依存版、機体・海況・風・seed、校正、補助、閾値。
- `inputs.jsonl`：受信seq、受信単調時刻、校正済み要求値。
- `ticks.jsonl`：採用seq、適用制御、正規状態、損傷、物理tick。
- `events.jsonl`：権限遷移、停止理由、拒否、通信品質、手順達成。
- `summary.json`：成績、終了理由、検証対象範囲。

記録キューには上限を持たせ、ディスク不足・書込み失敗は停止して告知する。summaryは一時ファイル＋置換で確定し、クラッシュ時は未完了セッションと識別する。

映像レビューは保存状態の再生を正とする。入力からの物理再実行は同じコード・環境で比較する別機能で、異なるNumPy/OS間のbit一致は保証しない。ログの任意学習利用は明示的同意がある場合のみ。初期版では人間ログを自動的に学生モデルへ投入しない。

## 11. 実装順序と受入条件

### P0：制御契約・状態機械

- FakePad相当の入力列で3モードをヘッドレス実行。
- AUTO中の人間入力不採用、引継ぎ未確認時の権限維持、切断停止、再開確認を試験。
- 接水と終了の定義を課程に固定。既存回帰テストを維持。

### P1：サーバー・校正・2D計器

- WSで入力とテレメトリを往復。有限値・範囲・epoch・seq・重複イベントを試験。
- 不正Origin、別セッション、同時操縦接続、洪水入力を拒否。
- FakeClockでwatchdog／overrunを決定的に試験。停止後の物理・損傷不変を確認。

### P2：3D外景・引継ぎ・ハイブリッド

- 描画座標・姿勢符号・海面時刻・海面高さ誤差を試験。
- 自動離水→手動飛行→進入→自動着水を通し実行。
- 引継ぎで許容以上の指令ジャンプがないことをtickログで確認。
- 対象PCで20Hz物理を維持、操縦席描画30FPS以上を最低目標に測定。60FPSは目標。

### P3：手動課程・採点・レビュー

- 保存状態再生と元ログの指標一致、同条件の評価、介入・中断の区別を試験。
- 故障、着水失敗、ディスク不足、低速クライアントでも理由付きで終了／停止。
- 未校正ゲート・未検証海況を正式評価に使用しない。

### P4：実機器受入

XboxとDualSense各1台以上でUSB試験。対象OS／ブラウザ版を記録し、認識・全軸・ボタン・抜差し・タブ切替・画面ロック・再接続を確認。Bluetoothは別試験項目とする。ブラウザ自動試験の仮想Gamepadだけで実機対応済みとしない。

同一PCとネットワーク経由を分けてRTT・適用遅延・描画遅延を測る。接水タイミングの訓練効果は経験者を含む利用試験で評価する。

## 12. 主要リスクと判断保留

| リスク | 対応 |
|---|---|
| 外景と波面の食違い | 同一海面・同一描画時刻、数値誤差試験 |
| 現行AUTOが任意状態に対応しない | 進入ゲート限定、課題航路設計、未達なら拒否 |
| 遅延を操縦能力と誤認 | 品質記録、停止、無効試行扱い |
| ピッチ直接指令による誤学習 | 限界の明記、手順訓練に限定、将来6DOF化を別計画 |
| 機器・ブラウザ差 | 校正、能力診断、実機器マトリクス |
| 描画・海面計算が物理を遅延 | 予算測定、有界キュー、物理所有の分離 |
| ログ肥大化 | Git非管理、削除／export、容量上限 |

着手前のブロッカーはなし。同一PC・USB・1操作者を基準にP0から進める。標準試験OS、進入ゲートの実測範囲、海面パッチ精度、各課程の合否閾値は実装・検証段階で確定する。
